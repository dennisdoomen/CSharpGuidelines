# Documentation & Comments (AV2300)

| Rule | Severity | Guideline |
|------|----------|-----------|
| AV2301 | Must | Write all comments and XML documentation in US English. |
| AV2305 | Should | Document every `public`, `protected`, and `internal` type and member with XML doc comments. |
| AV2306 | Should | Write documentation for other developers who don't have access to the source code. |
| AV2308 | Should | Document the purpose of a member (the *why* and *what*), not its implementation (the *how*). |
| AV2310 | Should | Avoid inline comments; replace complex blocks with well-named methods instead. |
| AV2316 | Must | Only write comments to explain non-obvious algorithms or significant design decisions. |
| AV2318 | May | Don't use `// TODO` comments as a task tracker; use a proper issue tracking system. |
